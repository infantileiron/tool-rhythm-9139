# 溪巷工坊·共享工具站节律分型

溪巷工坊是一个模拟的社区工具共用网络，设有 12 个修造站、邻里共享点和自助工具柜。协调组用一周的分时归还记录找到节律相近的站点，按组试排值守，再逐站核对异常。

## 工作背景

上游由站点联络人汇总工具柜日志与纸质回收联。过去，协调组在共享表格中手抄数据、画分时百分比、把值班意见发到群里。人手紧时，件数大的站点会盖过小站的节律，自助柜夜间归还容易被白班补记，表格改动也会让旧群消息失去依据。

柜机流水和纸联经常记的是同一件工具，部分纸联只剩小时和件数。本站先把两路归还记录导进台账逐站对账：重复登记只计一次，有争议的件数不计实收。再冻结一次分型用到的站点名单、日期、参数与归还向量。负责人拿到三个输入量级的区分：可以按组安排的站点、需要逐站核实的例外、完全缺数据的站点。分型页面可逐站追溯每一版用了哪些记录、哪些还没对上。发布后，站点联络人可通过 CSV 逐站领取值守或复核任务。

| 账号 | 角色 | 页面权限与典型动作 |
|---|---|---|
| `analyst` 周禾 | 分析员 | 登记站点、补录和校正分时归还，提交计算版本，查看全部分型与已发布值班单 |
| `admin` 韩宁 | 值班负责人 | 查看全部分型，修改各组建议，填写每个例外的处置意见并发布 |
| `observer` 宋可 | 观察员 | 只读站点和归还台账，查看已发布的分型和值班单，下载 CSV |

## 对账口径

- 两路联单按「站点 / 日 / 小时」槽位对账。柜机流水必须带站点与日期；纸联可只剩「小时, 件数」两列，缺的站点/日期用导入批次的默认值补齐，仍缺的行保留为「待落位」，不进入实收。
- 同槽内如果已有**人工台账记录**，以人工记录为准，导入行标为重复，不再计件。
- 两路同槽件数相同 → 视为同一件工具，只计一次（`paired`）；件数不同 → 取**较小值**计入实收，差额作为争议件数（`disputed`），**不计实收**。
- 只有一路的槽位按单边实收计入，仍可参与分型；导入行若与台账已有同通道记录冲突（件数不同），整批拒绝并提示改用人工校正合并。
- 同一文件按内容 + 默认值 + 窗口计算指纹；重跑同一批直接返回原批次（`replayed`），不新增记录、不重复计件。

## 对不上时的分型判定

站点对账状态分四档，决定该站能否分型：

| 状态 | 判定条件 | 分型处理 |
|---|---|---|
| `clean` 已对账 | 全部槽位成对或单边，无争议、无待落位 | 正常参与分型 |
| `partial` 部分对上 | 有可计入实收，但有少量争议或待落位记录 | **照常分型**（实收达到门槛时），未对上记录只在追溯中列出 |
| `unreconciled` 未对账 | 没有可计入实收（全部缺站点/日期），或争议件数 ≥ 凭证量一半 | **不参与分型**，列为例外 `unreconciled`，待补齐或核实后重算 |
| `no_data` 无记录 | 窗口内没有任何记录 | 列为例外 `no_data`，联系站点确认开放与漏录 |

判定阈值 `DISPUTE_SHARE = 0.5` 位于 `backend/src/constants/domain.py`。争议件数不计实收、但会进入凭证量（实收 + 争议）参与占比判断。

## 分型口径与复算

- 输入日期按北京时间，起止日均含。小时先归入本地半开时段 `[00,08)`、`[08,11)`、`[11,14)`、`[14,17)`、`[17,20)`、`[20,24)`。每站按窗口对六段**实收**件数求和，缺失时段按零填充。整站零件为「无记录」，正数但低于门槛为「低样本」，未对账为「未对账」。
- 对进入计算的向量 `x` 做 L2 归一化。余弦距离 `d(x,y) = 1 − (x·y)/(||x||₂||y||₂)`。闭邻域使用 `d ≤ ε`，容许 `1e-12` 的浮点误差，邻居计数含本站。
- DBSCAN 以编号排序的核心站扩展密度连通组，同行遍历邻居时也按编号排序。可达多组的边界站归到先扩展的组。未归入任何组的合格站标作「失群」。`G01` 等编号的作用域为当前版本。
- 画像按站等权。每站 `p[i] = x[i]/sum(x)`，组画像为各站 `p` 的算术平均，最高占比对应主峰。相同时取最早时段。并列结果和低样本情形都可读，空合格集会产出零组及逐站诊断。
- 每个版本保存算法标识 `cosine-dbscan-v2`、参数、时段边界和站点向量（实收、争议、凭证、对账状态）、名称、编号，以及所用记录与待落位记录的引用。对规范化的 UTF-8 JSON（键排序、无空格）计算 SHA-256。相同快照产生相同指纹与结果，后来补录、修改参数或新增站点只影响新版本。
- 「记录追溯」按版本快照里的记录引用回溯：每站列出所用记录与还没对上的记录，后来补录不会改变旧版本的用数。
- MySQL 保存任务和结果。Redis 唤醒 worker，轮询兜底。worker 用连接级互斥锁按版本号串行消费，进程中途退出后可重新领取未完成版本。快照校验或计算错误会留下失败态。发布与审计在同一事务内落库。

## 已知限制

单次日期窗口为 1–93 天、最多 250 站，邻域比较为平方复杂度。当前录入粒度是站点/日/小时汇总，来源联单作为文本留存；同槽多张纸联按行拆开后相加，再与柜机比对，无法逐件配对到同一件工具。纸联缺日期时只能用批次默认日期补齐，否则保留为待落位。窗口全零无法区分休站、漏录和确实无人归还，需要联系站点核实。节律分组反映归还分布，实际值守人手由负责人结合工具类型和现场负荷安排。应用为本地模拟环境，外部字体不可用时会使用本机中文字体。源代码按 MIT License 提供。
