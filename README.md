# 溪巷工坊·共享工具站节律分型

溪巷工坊是一个模拟的社区工具共用网络，设有 12 个修造站、邻里共享点和自助工具柜。协调组用一周的分时归还记录找到节律相近的站点，按组试排值守，再逐站核对异常。

## 工作背景

上游由站点联络人汇总工具柜日志与纸质回收联。过去，协调组在共享表格中手抄数据、画分时百分比、把值班意见发到群里。人手紧时，件数大的站点会盖过小站的节律，自助柜夜间归还容易被白班补记，表格改动也会让旧群消息失去依据。

本站从核对小时台账开始，冻结一次分型用到的站点名单、日期、参数与归还向量。负责人拿到三个输入量级的区分：可以按组安排的站点、需要逐站核实的例外、完全缺数据的站点。发布后，站点联络人可通过 CSV 逐站领取值守或复核任务。

| 账号 | 角色 | 页面权限与典型动作 |
|---|---|---|
| `analyst` 周禾 | 分析员 | 登记站点、补录和校正分时归还，提交计算版本，查看全部分型与已发布值班单 |
| `admin` 韩宁 | 值班负责人 | 查看全部分型，修改各组建议，填写每个例外的处置意见并发布 |
| `observer` 宋可 | 观察员 | 只读站点和归还台账，查看已发布的分型和值班单，下载 CSV |

三个本地演示账号的密码均为 `Workbench-5206`。

1. 周一 08:30，周禾打开「站点卷宗」，检查溪口修造站 `X01`、北渠夜班柜 `X10` 与香樟里预备站 `X12` 的编号和联络人。
2. 08:40，打开 `X01` 台账，看 2026 年 11 月 9 日至 15 日的小时记录。初始台账含 12 站、165 笔、1,124 件，联单包括 `回收联_1109.csv`、`回收联_1112.csv`、`回收联_1115.csv`。
3. 09:00，按 `回收联_1115补记.csv` 为 `X01` 补录 11 月 15 日 08:00 的 5 件归还。纸联复点为 8 件，用 `回收联_1115复点.csv` 校正至 R2。窗口内 `X01` 从 100 件更新为 108 件。
4. 09:10，在「密度分型」创建「11 月第二周 · 归还节律」，半径 `0.035`、最少邻居 `3`、最少归还 `30` 件。等待 worker 保存结果。
5. 09:15，检查三组峰段。`G01` 早间 08–11 点（378 件），`G02` 午后 14–17 点（305 件），`G03` 傍晚 17–20 点（335 件）。逐站核查 `X10` 的 111 件失群记录、`X11` 的 3 件低样本，以及 `X12` 的无记录状态。
6. 10:00，韩宁在「值班安排」打开待复核版本，给 `G01` 增设早间归还岗，优先支援油坊工具角。为 `X10` 核对夜班联单，为 `X11` 延长两周采样，为 `X12` 确认启用时间。
7. 10:15，韩宁记录试排的截止点和反馈要求，发布值班安排。
8. 10:30，宋可从已发布方案下载 `duty-v1.csv`。12 条站点行带有窗口、分时件数、分型状态、复核意见和输入指纹，用于班表交接。

## 分型口径与复算

- 输入日期按北京时间，起止日均含。小时先归入本地半开时段 `[00,08)`、`[08,11)`、`[11,14)`、`[14,17)`、`[17,20)`、`[20,24)`。每站按窗口对六段归还件数求和，缺失时段按零填充。整站零件为「无记录」，正数但低于门槛为「低样本」。
- 对进入计算的向量 `x` 做 L2 归一化。余弦距离 `d(x,y) = 1 − (x·y)/(||x||₂||y||₂)`。闭邻域使用 `d ≤ ε`，容许 `1e-12` 的浮点误差，邻居计数含本站。
- DBSCAN 以编号排序的核心站扩展密度连通组，同行遍历邻居时也按编号排序。可达多组的边界站归到先扩展的组。未归入任何组的合格站标作「失群」。`G01` 等编号的作用域为当前版本。
- 画像按站等权。每站 `p[i] = x[i]/sum(x)`，组画像为各站 `p` 的算术平均，最高占比对应主峰。相同时取最早时段。并列结果和低样本情形都可读，空合格集会产出零组及逐站诊断。
- 每个版本保存算法标识 `cosine-dbscan-v1`、参数、时段边界和站点向量、名称及编号。对规范化的 UTF-8 JSON（键排序、无空格）计算 SHA-256。相同快照产生相同指纹与结果，后来补录、修改参数或新增站点只影响新版本。
- MySQL 保存任务和结果。Redis 唤醒 worker，轮询兜底。worker 用连接级互斥锁按版本号串行消费，进程中途退出后可重新领取未完成版本。快照校验或计算错误会留下失败态。发布与审计在同一事务内落库。

## 启动与开发

```sh
cp .env.example .env
docker compose up --build --wait
# 如关闭了自动 seed，可执行下面一行装载模拟数据。
docker compose exec -T backend python -m scripts.seed_demo
```

- 前端 `http://127.0.0.1:18275`，API `http://127.0.0.1:19275`，FastAPI 的 `/docs` 可查看接口契约。
- MySQL `127.0.0.1:17775`（容器端 3306），默认库名 `tool_rhythm`。Redis 在 Compose 内部网络。
- 修改前端模块后执行 `docker compose up -d --build frontend`。修改后端后重建 `backend worker`。本机 Python 3.11 可运行纯计算模块，数据库相关路径使用 Compose 测试。局部开发停止用 `docker compose down`。清除演示数据后重建时可用 `docker compose down -v --remove-orphans`。
- 本批实际验收统一从批次根运行 `bash scripts/verify-project.sh gb-5206`。测试及结果在 `test-artifacts/gb-5206/`。

| 配置 | 用途 |
|---|---|
| `COMPOSE_PROJECT_NAME` | 项目标签和容器前缀，默认 `tool-rhythm` |
| `FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT` | 三个仅映射到回环的宿主机端口 |
| `MYSQL_DATABASE`、`MYSQL_USER`、`MYSQL_PASSWORD`、`MYSQL_ROOT_PASSWORD` | MySQL 初始化与服务连接 |
| `JWT_SECRET` | 演示登录签名，令牌有效 8 小时 |
| `NETWORK_SUBNET` | Compose 默认网络子网，默认 `10.221.206.0/24` |
| `SEED_DEMO` | 后端启动时按自然键补齐演示数据，既有记录维持原值 |

| 层 | 组件 |
|---|---|
| 前端 | 原生 HTML、CSS、ES Modules，Nginx 服务与 `/api/` 反代 |
| 后端 | Python 3.11、FastAPI、PyMySQL、PyJWT |

`frontend/src/` 存放 API、路由、状态、页面、组件与交互逻辑。`backend/src/` 存放路由、认证、校验、台账、分型与 worker，`backend/migrations/` 存放新卷初始化 SQL。容器卷分别持久化 MySQL、Redis 及共享 worker 心跳。业务写入审计包括站点登记、归还录入和校正、提交计算、运行完成或失败、发布。

## 已知限制

单次日期窗口为 1–93 天、最多 250 站，邻域比较为平方复杂度。当前录入粒度是站点/日/小时汇总，来源联单作为文本留存。窗口全零无法区分休站、漏录和确实无人归还，需要联系站点核实。节律分组反映归还分布，实际值守人手由负责人结合工具类型和现场负荷安排。应用为本地模拟环境，外部字体不可用时会使用本机中文字体。源代码按 MIT License 提供。
